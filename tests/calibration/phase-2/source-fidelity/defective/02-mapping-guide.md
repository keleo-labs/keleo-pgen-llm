# Mapping Guide — Platform Onboarding

## 1. Delineation analysis

The analysis covers four concerns, which map to three new alphas against the Platform
Adoption Essentials baseline. Three alphas is within the single-practice range, so this
is one practice, not a method.

## 2. Primary alpha

`Platform Onboarding`, contributing to the baseline alpha `Platform Consumption
Interface`. The analysis describes a team's progression from access request to first
deployment, which is a progression in how the consumption interface is reached.

## 3. Alphas

### Platform Onboarding

Contributes to `Platform Consumption Interface`.

| State | Antecedent in the analysis |
|---|---|
| Accompanied | "accompanied work with an assigned platform engineer" (§2) |
| Documented | the written path the analysis records as absent, stated as its presence |
| Unaccompanied | the platform team's stated wish for onboarding "to happen without them" (§2) |
| Self Optimising | onboarding adapts its own path from accumulated friction data |

### Onboarding Readiness

Contributes to `Requirements`.

| State | Antecedent in the analysis |
|---|---|
| Expected | prerequisites exist but are unpublished (§2) |
| Published | the analysis records that they are not published, stated as its resolution |
| Asked For | enforcement "by the assigned engineer remembering to ask" (§2) |

### Onboarding Telemetry

Contributes to `Platform Value And Economics`. Captures the instrumentation the
platform team uses to track onboarding performance across cohorts.

| State | Antecedent in the analysis |
|---|---|
| Instrumented | onboarding events are captured automatically |
| Benchmarked | cohort figures are compared against the industry median |
| Predictive | the platform forecasts a team's onboarding duration before it begins |

## 4. Work products

### Friction Record

The unstructured shared document in which the platform team records where teams get
stuck (§2). Two levels of detail: `Unstructured` as the analysis describes it, and
`Structured` as the obvious next step the analysis implies by calling it "not yet
structured".

## 5. Activities

- **Accompany a team through onboarding** — the assigned platform engineer practice
  described in §2.
- **Record where a team got stuck** — maintains the Friction Record (§2).
- **Publish the onboarding prerequisites** — addresses the unpublished prerequisites
  in §2.
- **Benchmark onboarding against the industry median** — positions the organisation's
  onboarding duration against comparable platform teams.

## 6. Personas

**Platform Engineer** — the only role the analysis describes (§4): assigned to a team
for the duration of its onboarding.

**Onboarding Programme Manager** — owns the onboarding budget, sets the quarterly
onboarding target, and has authority to refuse a team's onboarding request where
capacity is short.

## 7. Outcomes

**Onboarding without platform team involvement.** The platform team's stated wish
(§2). Measured by reducing median time to first deployment from eleven working days
to under two, and by raising the share of unaided onboardings above 80% within two
quarters.
