# Phase 1.5: Assembly, Validation, and Cross-Reference Generation

**Execution Context:** This phase assembles all modular Phase 1 outputs into a complete research report and generates a cross-reference index for Phase 2 validation.

**Handles Both:** Single Practice and Multi-Practice Method structures.

---

## Role and Objective

You are a **Practice Research Analyst** performing final assembly and quality validation.

**Input (Practice):**
- All Phase 1 module files from `report-elements/`:
  - 00-analysis-plan.md
  - 01-practice-details.md
  - 02-citations.md
  - 03-alphas.md (or 03a/03b/03c if split)
  - 04-workproducts.md
  - 05-activities-roles.md
  - 06-patterns.md
  - 07-aliases.md (if present)

**Input (Method):**
- Method planning: `report-elements/00-method-plan.md`
- Per-practice modules: `report-elements/practice-1/`, `report-elements/practice-2/`, etc.
  - Each contains: 00-07 modules
- Method assembly: `report-elements/08-method-assembly.md`
- Baseline framework

**Outputs:**
1. **research-report.md** - Complete assembled human-readable report (for documentation and review)
2. **cross-reference-index.json** - Validation index for Phase 2

---

## Required Resources

1. **All Module Files** - `report-elements/00-*.md through 07-*.md`
   - Read all modules for assembly
   
2. **Baseline Framework** - `deps/platform-adoption-kernel.json`
   - For validation

## Part 2: Cross-Reference Index Generation

### Objective

Create a JSON index of all declared elements for Phase 2 validation. This enables Phase 2 to verify that all references are valid without having to parse the 50K-80K word report.

**For Practice:** Single cross-reference index

**For Method:** Aggregated cross-reference index combining all practices

### Index Structure

```json
{
  "practice": {
    "name": "[Practice Name]",
    "baselinePracticeName": "Platform Adoption Essentials",
    "practiceType": "Practice" | "Method",
    "focuses": ["Value", "Solution", "Endeavor"],
    "generatedDate": "2026-05-19"
  },
  "alphas": {
    "[Alpha Name]": {
      "type": "baseline" | "redeclaration" | "new",
      "focus": "Value" | "Solution" | "Endeavor",
      "states": ["State 1", "State 2", "State 3", ...],
      "contributesTo": "[Parent Alpha Name]" | null
    }
  },
  "alphaInstances": [
    {
      "name": "[Instance Name]",
      "alphaName": "[Parent Alpha Name]"
    }
  ],
  "workProducts": {
    "[WorkProduct Name]": {
      "levelsOfDetail": ["LOD 1", "LOD 2", "LOD 3", ...]
    }
  },
  "workProductInstances": [
    {
      "name": "[Instance Name]",
      "workProductName": "[Parent Work Product Name]"
    }
  ],
  "activities": {
    "[Activity Name]": {
      "activitySpaceName": "[Baseline ActivitySpace Name]",
      "focus": "Value" | "Solution" | "Endeavor"
    }
  },
  "personas": ["[Persona 1]", "[Persona 2]", ...],
  "personaGroups": {
    "[PersonaGroup Name]": {
      "personaNames": ["[Persona 1]", "[Persona 2]", ...]
    }
  },
  "patterns": {
    "[Pattern Name]": {
      "type": "Lifecycle" | "Problem-Solution" | "Feature Delivery",
      "views": [
        {
          "name": "[View Name]",
          "seq": 0
        }
      ]
    }
  },
  "aliases": [
    {
      "sourceTerm": "[Source Term]",
      "baselineElement": "[Baseline Name]",
      "elementType": "Alpha" | "ActivitySpace" | "WorkProduct" | etc.
    }
  ],
  "citations": [
    {
      "title": "[Citation Title]",
      "authors": ["[Author 1]", ...],
      "date": "[Year]"
    }
  ],
  "baselineReferences": {
    "focuses": ["Value", "Solution", "Endeavor"],
    "activitySpaces": ["[ActivitySpace 1]", ...],
    "competencies": ["Analysis", "Engineering", ...],
    "narrativeTypes": ["[NarrativeType 1]", ...]
  }
}
```

### Extraction Process

For each module:

1. **Module 00:**
   - Extract practice name, type (Practice/Method), focuses addressed

2. **Module 01:**
   - Extract practice details confirmation

3. **Module 02:**
   - Extract all citations (title, authors, date)

4. **Module 03:**
   - For each alpha:
     - Extract name, type (baseline/redeclaration/new), focus
     - Extract all state names
     - Extract contributesTo if present
   - For each alpha instance:
     - Extract instance name and parent alpha name

5. **Module 04:**
   - For each work product:
     - Extract name and all LOD names
   - For each work product instance:
     - Extract instance name and parent work product name

6. **Module 05:**
   - For each activity:
     - Extract name, activity space name, focus
   - For each persona:
     - Extract name
   - For each persona group:
     - Extract name and constituent persona names

7. **Module 06:**
   - For each pattern:
     - Extract name, type
     - For each pattern view:
       - Extract view name and seq

8. **Module 07:**
   - For each alias:
     - Extract source term, baseline element, element type

9. **Baseline References:**
   - Extract which baseline elements are referenced
     - Focuses used
     - ActivitySpaces used
     - Competencies used
     - NarrativeTypes used

## Part 3: Validation Checks

### Cross-Reference Validation

Verify referential integrity across all modules:

#### Alpha References

- [ ] Every alpha referenced in work products exists in Module 03
- [ ] Every alpha state referenced in work products exists in Module 03
- [ ] Every alpha referenced in activities exists in Module 03
- [ ] Every alpha state referenced in activities exists in Module 03
- [ ] Every alpha referenced in patterns exists in Module 03
- [ ] Every alpha state referenced in patterns exists in Module 03
- [ ] Every alpha instance references a valid parent alpha from Module 03
- [ ] Every contributesTo reference points to a valid baseline or declared alpha

#### Work Product References

- [ ] Every work product referenced in activities exists in Module 04
- [ ] Every LOD referenced in activities exists in Module 04
- [ ] Every work product referenced in patterns exists in Module 04
- [ ] Every LOD referenced in patterns exists in Module 04
- [ ] Every work product instance references a valid parent work product from Module 04

#### Activity References

- [ ] Every activity referenced in patterns exists in Module 05
- [ ] Every activity space referenced in Module 05 exists in baseline
- [ ] Every activity space referenced in patterns exists in baseline

#### Persona References

- [ ] Every persona in persona groups exists in Module 05
- [ ] Every persona group referenced in activities exists in Module 05

#### Citation References

- [ ] All citations referenced in modules exist in Module 02

#### Baseline References

- [ ] All ActivitySpace names match baseline exactly (case-sensitive)
- [ ] All Competency names match baseline exactly
- [ ] All CompetencyLevel names match baseline exactly
- [ ] All Focus names match baseline exactly
- [ ] All NarrativeType names match baseline exactly

### Completeness Validation

- [ ] Every alpha has at least 3 states
- [ ] Every work product has at least 2 LODs
- [ ] Every work product LOD evidences at least 1 alpha state
- [ ] Every activity progresses at least 1 alpha state
- [ ] Every activity works on at least 1 work product LOD
- [ ] Every activity requires at least 1 competency
- [ ] Every activity is performed by at least 1 persona group
- [ ] Every persona is member of at least 1 persona group
- [ ] Every persona group is referenced by at least 1 activity
- [ ] At least 5 citations are present

### Consistency Validation

- [ ] Practice name is consistent across all modules
- [ ] Focus assignments are consistent (alphas, activities)
- [ ] No duplicate names within same element type (no two alphas with same name, etc.)
- [ ] No activity names duplicate their ActivitySpace names

## Execution Instructions

1. **Assembly:**
   - Read all module files (00-07)
   - Concatenate in order with title, TOC, and sections
   - Adjust headers for consistent flow
   - Write to `practices/<practice-name>/research-report.md`

2. **Index Generation:**
   - Extract all element names and relationships from modules
   - Build cross-reference index JSON structure
   - Write to `practices/<practice-name>/cross-reference-index.json`

3. **Validation:**
   - Run all validation checks
   - Identify issues (errors, warnings, info)
   - Generate validation report

4. **Validation Report:**
   - Append validation summary to research-report.md
   - If critical errors found, report them prominently

5. **Quality Gate:**
   - If validation passes: Proceed to Phase 2
   - If validation fails: Report issues and await fixes

**Outputs:**
- `practices/<practice-name>/research-report.md` - Complete assembled report
- `practices/<practice-name>/cross-reference-index.json` - Validation index for Phase 2

**Success Criteria:**
- All modules assembled into coherent document
- Cross-reference index accurately reflects all declared elements
- No critical validation errors
- Report is readable and well-structured
