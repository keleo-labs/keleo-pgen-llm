# Diagram Guide

How to produce diagrams for reports. Read this when a report needs a visual — during planning if the
report type always has one (reference architecture), otherwise at Step 3 when you reach the section.

Diagrams are **rendered SVG**, generated by `utils/render-diagram.py` from a small JSON spec. Never
hand-draw ASCII art, and never hand-write SVG geometry — `lint-report.py --checks diagrams` fails the
report on the first, and the second produces overlapping boxes and clipped labels.

---

## When a diagram earns its place

A diagram is worth the space when the content is **structural** — components and the connections
between them, a sequence with dependencies, a containment hierarchy. It is not worth the space when
the content is **comparative or quantitative**; those are tables.

| Content | Use |
|---|---|
| Components and how they connect | `flow` diagram |
| Options scored across dimensions | Table |
| Layers resting on one another | `stack` diagram |
| Phases in order, with dependencies | `timeline` diagram |
| One thing related to several others | `hub` diagram |
| Capacity figures, node counts, sizing | Table |
| A list of three things | Prose or a list |

Two or three diagrams in a report is normal. Six is a sign that tables are being drawn as boxes.

---

The engine is shared. `.claude/skills/diagram-foundation/DIAGRAM-FOUNDATION.md` carries the spec
reference, the design tokens and the rationale; this guide covers only what a report author needs.
The deck skills use the same engine, which is why a diagram's spec — not its SVG — is the artifact
worth keeping.

## Layout selection

| Layout | Shape | Reach for it when |
|---|---|---|
| `flow` | Layered boxes, directed edges, optional cluster groups | Topologies, pipelines, data paths, process flows. The default. |
| `stack` | Vertical tiers | Layer models, maturity stacks, architecture tiers |
| `timeline` | Sequential phase bands joined by arrows | Roadmaps, adoption journeys, phased rollouts |
| `hub` | Centre node with satellites on an ellipse | Relationship maps, integration fan-out, event sources |

Run `python3 utils/render-diagram.py --spec-help` for the full field reference. Do not inline that
output into a subagent prompt — point the agent at the command.

## Workflow

**1. Write the spec** next to where the SVG will live, using the Write tool:

```
reports/
  <report-slug>.md
  assets/<report-slug>/
    option-a-topology.json
    option-a-topology.svg
```

The spec is kept, not discarded — it is how the diagram gets corrected later without redrawing it.

**2. Render every spec in one call** once all specs for the report are written:

```bash
python3 utils/render-diagram.py --dir reports/assets/<report-slug>/
```

Batch mode writes each `<name>.svg` beside its `<name>.json`. One call per report, not one per
diagram.

**3. Embed with a relative path and real alt text:**

```markdown
![Option A: controller-centric scheduled remediation topology](assets/<report-slug>/option-a-topology.svg)
```

## Writing a good spec

**The title is not drawn.** `title` and `description` become the SVG's `<title>` and
`<desc>`/`aria-label` — metadata for screen readers, never artwork. The heading above the diagram
in the report already names it, so a rendered title would print the same line twice. Set both
fields anyway; they cost nothing and they are what a non-sighted reader gets.

**Labels are noun phrases, not sentences.** "Automation controller", not "The automation controller
runs scheduled scans". Detail belongs in `sublabel` or in the prose around the diagram.

**Three to nine nodes.** Below three, prose is clearer. Above nine, split the diagram or raise its
level of abstraction.

**Use `emphasis` sparingly.** One or two `accent` nodes draw the eye to what matters; everything
accented is nothing accented. `muted` recedes a node that is context rather than subject.

**Label the edges that carry meaning.** "scheduled scan" earns its place; "connects to" does not.

**Group when containment is part of the point** — a trust boundary, a network zone, a vendor
boundary. Not merely to tidy the layout.

**The diagram supplements the prose, it does not replace it.** A reader who cannot see images must
still follow the argument. Alt text carries the diagram's claim, not a list of its boxes.

## Styling

The visual language comes from the keleo-studio-gas navigator, so reports, the studio UI and the
deck theme read as one system. Tokens live in the `THEME` dict at the top of
`utils/render-diagram.py` — change them there, never per-diagram. Specs carry content and structure
only; they do not set colours, fonts or sizes.

---

## Decks are different

The deck skills deliberately avoid SVG — it does not survive the PowerPoint to Google Slides
conversion (`deck-foundation/DECK-FOUNDATION.md` §"conversion safety"). This guide applies to
reports only.
